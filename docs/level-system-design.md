## 1. Fun Hypothesis 与 Design Pillars

**Fun Hypothesis**：这游戏好玩的核心是 **「在越来越密的压力下，始终清楚下一秒该先杀谁」**——目标优先级决策带来的心流，而不是单纯的枪法。

**Design Pillars**（之后每个设计决策都用这四条过审）：

| # | 支柱 | 含义 | 反例（违反即砍） |
|---|------|------|------------------|
| P1 | **每关只教一件事** | 新怪/新枪/新场地引入关，其余变量保持克制 | 一关同时塞新怪+新场地+数值暴涨 |
| P2 | **压力可读，死的明白** | 每个伤害来源必须有预警（吟唱/抬臂/体型），玩家阵亡能说出"我该先杀那个" | 任何无前摇的伤害 |
| P3 | **1-3 分钟常规关，Boss 关 3-5 分钟** | 碎片时间可完成一局；通不了关的原因是决策不是数值墙 | 同一场常规战斗超过 4 分钟 |
| P4 | **数值必须能讲出为什么** | 每个数字后面挂着推导或 `[PLACEHOLDER]`，禁止 magic number | "先填个 999 跑跑看" |

**关键推导锚点（后续所有曲线以此为基准）：**

- **玩家有效 DPS（设计锚点）= 125** ✅：完整推导链——
  循环上限 200（30 发 × 34 ÷ 5.1s 循环，含 1.5s 换弹）
  × 命中率 50%（设计目标玩家）
  × 爆头伤害系数 1.25（爆头率 25% → 均伤 42.5/34）
  = **125**。（瑕疵 3 收口：全文统一以 **125** 为底数，§4 不再取整 120。）
  - **敏感性**：命中率每 ±10pp → DPS ±25 → 全文血池 ±20%（同方向：DPS 高则血池需同比放大以维持设计时长）。M0 标定的输出是**一个全局血池缩放系数**，不是逐格改表。
- **M0 标定结果（✅ 已实测，n=14 有效样本，多玩家）**：实测命中率 **70.66%**（289/409）、爆头率 **32.18%**（93/289）。
  - 校准后真实 DPS = 200 × 0.7066 × (1 + 0.3218) = **187**（远高于设计锚点 125，触发 §10 A 级「血池重算」信号）。
  - **全局血池缩放系数 k = 187 ÷ 125 ≈ 1.50** ✅：§4 常规关（L1–L6）血池在**实现时 ×1.50**（配置以单个全局 `hpCalibMul: 1.5` 承载，不改逐关 composition）。因血池与 DPS 同比放大，**纯输出时长（设计时长锚点）保持不变**。
  - **适用范围**：k 仅作用 L1–L6。**Boss（L7，§5.3）不吃 k**——Boss 用自身大体型假设（命中 65% / 爆头 40%）独立推导，属 ⚗️ 未标定项，延至 M5a 首战计时收口。
  - **注意**：k 只缩放血量，不缩放怪物伤害（§2 容错 红4掌/蓝10发 不变）——只校准「击杀耗时」，不改「被打死耗时」。L1 教学关单只红怪将变为 225 HP（≈7 发身体），若 playtest 觉得开局肉手，优先用「增数量 而非 加单血」回调（交 M6）。
- **玩家容错 = 红 4 掌 / 蓝 10 发** ✅：100 HP 无回血，这是每关「压力预算」的分母。

## 3. 元循环三层钩子

```
Moment(0-30s)   看到怪 → 判断优先级 → 射击/走位 → 命中反馈（血条/闪烁/音效）
Session(1-3min) 进入关卡 → 压力递增 → 杀光/Boss 倒地 → 评级结算 → 解锁下一关
Long-term(小时) 通关 L7 + 每关刷 S 评级 + 收集 3 把武器
                        ↳ localStorage 持久化，刷新不丢
```

**长期钩子的边界（明确不做）**：不做金币/商店（多一个货币就要回答"买什么"的新决策链，且 source 没有对应 sink，通胀预定）；不做天赋树（与"枪法+决策"的核心无关）。想加是另一个项目。

**L1 教学提示条实现规格**：
- 触发条件：对应按键首次被按下（W/A/S/D 任一 → 移动提示消失；mouse move delta>5px → 瞄准提示消失；R → 换弹提示消失；Shift → 疾跑提示消失；mouse left button down → 射击提示消失（第 5 bit））
- 显示位置：屏幕下方 20% 高度居中，半透明黑底白字条（`position:absolute; bottom:20%; left:50%; transform:translateX(-50%)`）
- 动画：opacity 0→1（0.3s ease-in），触发后 1→0（0.5s ease-out）+ display:none
- 持久化：写入 localStorage `wk.pve.tutorial.done` bitmask（5 bit），重玩 L1 不重复显示
- 优先级：同时只展示 1 条（按 WASD→鼠标→R→Shift 顺序解锁下一条）

\* 纯输出时长 = **校准后血池（已 ×k1.5）÷ 校准 DPS 187**（等价于 composition 血池 ÷ 设计锚点 125，故时长锚点不因 k 改变），只含开枪时间，不含追逐拉扯。预估单关实机时长 = 该值 ×6~10（⚗️ playtest 标定 P3 是否成立）。L1-L2 实机 ≈30-65s（教学关，短即对），L3-L6 实机 ≈1-2.5min（符合 P3 常规关 1-3min），L7 Boss ≈2.5-3.5min（符合 P3 Boss 关 3-5min）。

**难度曲线形状**：L1→L3 缓坡（建立信心），L4 第一个尖峰（新怪种+新枪同时给，用新工具解压），L5 回落蓄力，L6 陡峰（毕业考），L7 机制峰（考学习不考数值）。

L3 武器限制：霰弹枪为 L3 **通关奖励**，L3 关内不可用（进入 L3 时 `weapons` 列表仍只有 AK）。理由：L3 教学点是"窄位拉扯"，若关内给霰弹枪则贴脸喷射成为更优解，教学点被绕过。与 §7 存档设计一致——`weapons` 数组写入时机为"过关结算时"。

L4 教学负载说明：霰弹枪是 **L3 通关奖励**，L4 开始时玩家已持有。但 L4 的蟹群设计让霰弹并非唯一解——蟹 HP 68（2 发 AK / 1 发霰弹近距），4 只蟹 + 3 红 + 2 蓝的混编意味着"贴脸用霰弹清蟹 → 切 AK 处理远处蓝怪"的武器切换本身就是目标切换教学的一部分。教学点从"纯目标优先级"调整为"**在正确时机选正确武器 + 目标优先级**"——仍满足 P1"每关只教一件事"（一件事 = 目标切换与武器匹配的统一决策）。

### 4.1 新机制：同场上限 + 补位队列

- **Purpose**：L6 总数 11 只若同场，压力超出"可决策"上限（P2），且性能无必要承压。
- **规则**：同场活跃怪 ≤ **8** `[PLACEHOLDER]`；超出进 FIFO 队列，每有 1 只死亡动画**播完**（`removeMonster` 时机，与现有约定一致）补 1 只，入场点距玩家 ≥15m。
- **P2 合规条款**：入场点若落在玩家背后 90° 视锥内，必须先播 **1s 生成光柱预警**再可行动。否则「背后补位 → 落地即冲刺」= 无前摇伤害，直接违反 P2。
- **HUD**：剩余敌数 = 场上存活 + 队列（向玩家坦诚总账）。
- **Edge case**：队列补位触发时不打断任何进行中行为；Boss 关 adds 不走队列（Boss 阶段逻辑自管）。
- **入场点退化策略**：若全场地无满足 ≥15m 的合法点（变体 A 窄道布局可能发生），降级为 ≥10m；若仍无解，取距玩家最远的合法点 + 强制播 1s 光柱预警（无论是否在背后视锥内）。

## 5. 逐轴详细设计

### 5.1 数值递增轴

| 关卡 | 血量倍率 | 伤害倍率 | 追速倍率 | Rationale |
|---|---|---|---|---|
| L1-L2 | ×1.0 | ×1.0 | ×1.0 | 基线，教学期不动数值 |
| L3 | ×1.1 | ×1.1 | ×1.0 | 配合窄道场地，压力 +10% 可感知但不突变 |
| L4-L5 | ×1.1 | ×1.1 | ×1.0 | 新怪种是主角，旧怪数值保持 |
| L6 | ×1.2 | ×1.2 | ×1.05 | 毕业考，全面 +20%，速度 +5% 压缩风筝空间 |
| L7 | Boss 独立 | — | — | 见 5.3 |

**倍率作用域规则** ✅：倍率作用于**所有**怪种（含精英/新怪）；精英先按怪种基础 HP（精英红 300 / 精英蓝 220）再乘关卡倍率。

- 追速刻意压到 ×1.05 上限 ✅：红怪 5.0×1.05=5.25 仍低于疾跑 7.2，保证"疾跑一定能脱战"这条底层承诺不破（否则 P2 崩溃）。
- 倍率落在配置表，不写死在创建函数里（见 §8 配置 schema）。
- ⚠️ 本表倍率是**关卡间相对增量**，另需叠乘 §2 的**全局校准系数 k=1.50**：实际生成 HP = 怪种基座 HP × 本表关卡倍率 × k。两者相乘才等于 §4 血池列的值。

### 5.2 场地变化轴（2 套变体，不改碰撞系统）

复用现有 `registerSolid` 自登记机制——**布局即数据**：

- **变体 A「野区窄道」**：中路加 2 道横隔断，形成 3 条宽 2.5-4m 的走廊。⚠️ 走廊净宽必须 ≥0.8m 玩家直径 + 转弯余量（遵守现有间距约束，`registerSolid` 的 warn 会在摆放阶段拦截）。
- **变体 B「开阔祭坛」**：撤掉中央隔断，柱阵改为 2×3 对称双柱阵（精英/Boss 战风筝位）。
- **配置格式**：每关一个 `obstacles: [{type:'divider'|'pillar', x, z, w, d, h}, ...]` 数组，加载关卡时清场重建。
- **Edge case**：重建时必须同步清空 `solidObstacles` 并释放旧 geometry/material（与 `removeMonster` 释放约定同级）。

### 5.3 新怪种轴（3 种，全部程序化建模，零外部素材）

#### 迅捷蟹（L4 引入）— 「瞄准纪律的破坏者」

| 项 | 值 | Rationale |
|---|---|---|
| HP | 68（2 枪） | 让"打它值不值"成为真决策：2 发子弹换一片清净 |
| 速度 | 8.0 直线 / 转向角速度 ≤120°/s | 比疾跑 7.2 快→跑不掉；转向钝→横向滑步能甩（弱点可读，P2） |
| 伤害 | 5 / 扑击，冷却 2s | 单只刮痧，4 只围上来每秒 10——威胁来自数量 |
| 体型 | 0.6m 宽，贴地 | 视觉上明确"低头打"的新目标轴 |
| 行为 | Z 字突进 → 扑击 → 后跳拉开 | 三段都要有位移预警（后跳是节奏窗口） |

#### 精英石像（L5 引入）— 「集火与爆头的考卷」

- 红/蓝各自的强化版：精英红 HP = 150×2 = **300** / 精英蓝 HP = 100×2.2 = **220**（蓝怪基础低，纯 ×2 只有 200 太脆，不足以在 ×1.1 关卡倍率下制造集火决策窗口；×2.2 使其在 L6 首次出场时为 220×1.2 = **264 HP** ≈ AK 8 发（纯身体，264÷34=7.8）/ 6 发（含 25% 爆头，264÷42.5=6.2）/ 射手步枪 4 发（264÷85=3.1）的击杀成本），伤害 ×1.5，体型 ×1.3，魔纹改紫、宝石加大。
- 追速 ×0.9 ✅：精英是"压迫型坦克"不是"刺客"，速度降一档让玩家有风筝解（P2），但血池厚到风筝成本很高——这就是它制造的决策。
- 同场 ≤1 只 ✅：两只精英同时存在会把"先杀谁"变成"被谁撵"，决策变混沌。

#### Boss 主宰（L7）— 三阶段机制怪

| 项 | 值 | 说明 |
|---|---|---|

| 失败信号 | 玩家阵亡 → 回 L7 起点，**不清已解锁进度** | 重复挑战成本 = 一关时长，不是全部人生 |

† **Boss HP 推导**：
基准武器 AK-47（§5.4 原则：“AK 在任何关都不是错解”）。
1. 循环上限 = 30×34÷5.1 = 200
2. 大体型修正：命中率 65%（hitbox ×3），爆头率 40%（大体型头部占比高）
3. AK 爆头系数 = 1 + 0.40×(2-1) = **1.4**
4. 有效 DPS = 200×0.65×1.4 = 182；×85% 有效输出占比（转场无敌+清 adds 分火）= **155**
5. 纯输出 = 6000÷155 = **39s**
6. Boss 实机系数 ≈ ×2.5-3（相较常规关的 ×6-10 显著低：Boss 战场地封闭无追逐、adds 独立扣时间）。因此：39s × 2.5-3 ≈ 98-117s + 6s 转场 + 30s adds ≈ **2.2-2.6min**，考虑走位/闪避间隙上浮至 ≈**3.0-3.5min**（P3 Boss 关下限 3min）
7. 若玩家选用射手步枪：持续 DPS 上限 = 8×85÷5.8 = 117；有效 DPS = 117 × 0.65（大体型命中）× 1.6（爆头系数 1+0.4×1.5）× 0.85 = **≈104**；纯输出 = 6000÷104 ≈ **58s**（相较 AK 39s，比值为 **×1.49**）。时长上浮至 ≈3.5-4.5min，仍在 P3 Boss 关容忍带内。
⚗️ 首战若 <2min 或 >5min 则调整 HP。

### 5.4 武器解锁轴（2 把新枪，程序化低模，登记进 `SFX_FILES`/`WEAPON_SFX` 双配置）

| | AK-47（现有） | 霰弹枪「裂空」（L3 通关） | 射手步枪「穿云」（L5 通关） |
|---|---|---|---|
| 单发伤害 | 34（爆头×2） | 9×8 弹丸（每丸独立判定，爆头不加成） | 85（爆头×2.5=212） |
| 射速 | 0.12s | 0.8s | 0.5s |
| 弹匣/换弹 | 30 / 1.5s | 6 / 2.2s | 8 / 1.8s |
| 射程衰减 | 无 | 线性插值：0-12m 全伤(9/丸)，12-20m 线性降至 0，>20m 不判伤 | 无 |
| 定位 | 万金油 | **蟹群/贴脸的答案** | **精英/Boss 的答案** |
| 代价 | — | 远程无力、弹药经济差 | 近战泼水无力、容错低 |

- **弹丸散布规格**：8 弹丸在固定 cone 内均匀分布，半角 `pelletConeHalf: 4°`（近距 3m 处散布半径 ≈0.21m）。0-12m 内不额外扩角（射程衰减只改伤害不改散布）。**爆头不加成**（每丸独立判定，单丸恒 9 伤，见本表）。
  - **M4 验收（已按“爆头不加成”口径修正）**：击杀 68 HP 蟹需 `⌈68/9⌉ = 8` 丸命中（8×9=72 > 68 ✓）；**6–7 丸（54/63 伤）秒不掉**。而旧稿“≥ 87% 覆盖率”⇒期望命中 `8×0.87≈7` 丸⇒**贴脸单发并不保证秒蟹**。因此验收定为：**贴脸 3m 单发需 ≥8 丸命中（近距必杀）**；若实测 <8 丸，**收紧半角至 3°** 重测（或提升单丸伤害，二选一，不许悬空）。
  - ❗ 连带修正：本条与 §5.3“蟹 HP 68（1 发霰弹近距）”的表述仅在收紧半角后成立；若 4° 半角实测 <8 丸，“一发秒蟹”不成立，需在 M4 标定后同步修正 §4 L4 行与 §5.3 蟹描述。
- **性能约定**：8 弹丸共用 1 次开火事件，逐丸 raycast 但曳光合并为 ≤3 条（视觉足够、性能可控）；移动端弹丸数可降至 6（配置字段 `pelletCountMobile`）。Boss 血条叠加 70%/40% 阶段刻度线；精英体型 ×1.3 时血条 worldScale 同步 ×1.3。
- **设计原则** ✅：两把新枪都是"侧向展开"不是"上位替代"——AK 在任何关都不是错解，但特定场景新枪明显更优。若 playtest 出现"解锁后 AK 再没人用"，削新枪而不是 buff AK。
- **切枪规则**：桌面数字键 1/2/3，移动端 HUD 加切枪按钮；切枪 0.4s（无伤害窗口，不能用来取消后摇）；**切枪打断换弹**，弹药按现有 `RELOAD_MAG_IN_AT` 已判定状态结算（插弹匣前切走 = 白换）。未解锁键位置灰。
- **继承约定**：音效走 `WEAPON_SFX` 槽位映射，采样缺失回退合成音；后坐力/散布/弹道轨迹复用现有框架，新枪只改参数表。

## 6. 评级系统（S/A/B/F，替代现有二值 S/F）

| 档 | 条件（全部从 state 现成统计计算） |
|---|---|
| **S** | 命中率 ≥ **标定中位数 70.7% + 5pp ≈ 75%** ✅ **且** 爆头率 ≥**40%** **且** 未死亡 **且** 用时 ≤ parTime ×1.2 |
| **A** | 命中率 ≥ **标定中位数 70.7% − 5pp ≈ 65%** 且 未死亡 |
| **B** | 通关（保底） |
| **F** | 阵亡 |

- **S 档阈值的立场**：故意高于**标定中位数（70.7%）**——S 是「刻意追求」不是「认真玩的常态」，与 A 拉开档距。A/S 对称分布在中位数 ±5pp。
- **S 档爆头门 40% rationale** ✅：标定实测爆头中位数为 **32.2%**（§2），旧稿 35% 仅高于中位 2.8pp、不足以体现「刻意追求」；上调至 40%（≈中位 +8pp）。A 档不设爆头门。
- ⚠️ **已知张力（记账，M0 后决策）**：散布系统下高命中率偏好站桩输出，与 P1 教的「走位拉扯」存在激励冲突。候选处置：① S 附加条件改为「命中率 × 移动距离加权」；② 接受 S = 站桩流派。二选一，不许悬空。

**默认选择：候选 ②（接受 S = 站桩流派）**。理由：候选 ① 的加权公式引入新 magic number 违反 P4；且 S 档本就是"刻意追求"（§6 立场），与 A 档"移动流"分开两条路是可接受的产品分层。M0 标定后若数据显示 60% 以上玩家为达 S 而完全放弃走位（观测点：S 档玩家平均移动距离 < A 档 50%），翻案改候选 ①。（M0 标定：实测命中率高达 70.7%，侧面印证「高命中偏好站桩」，候选 ② 立场暂时成立。）
- **时间基准公式** ✅：`parTime = 纯输出时长 × 8（实机系数中位）`。S 档时间门 = `parTime × 1.2`（允许 20% 浮动）。例：L1 = 4.8 × 8 = **38.4s ≈ 38s**，S 门 = 46s。初版按公式生成，playtest 后按 P75 玩家用时收紧。⚗️
- **L7 Boss 关特殊规则**：Boss 实机系数为 ×2.5-3（§5.3 脚注），不适用常规 ×8 公式。L7 `parTime = 180s`（Boss 实机中位 3min），S 门 = 180×1.2 = **216s**（3.6min）。M5a 首战后按 P75 玩家用时收紧。§8.1 `LEVELS[6]` 对应配置：`parTime: 180`。
- **武器差异容忍**：parTime 基于 AK（最高持续 DPS）计算。射手步枪的有效 DPS 比 AK 低约 **×1.5**（同口径修正后），S 档时间门 `×1.2` 余量不足。故步枪关卡默认配 `parTimeMul: 1.5`；playtest 若步枪玩家 S 达成率 >20% 可回收此修正。

**M0 标定已完成 → 启用动态阈值**：`calibratedAccuracyMedian: 70.7` + `sAccuracyOffset: 5` → S 命中率门 = 75.7%；`aAccuracyOffset: -5` → A 命中率门 = 65.7%。`calibratedHeadshotMedian: 32.2`（S 爆头门 40% 另置）。fallback 固定阈值 `sAccuracyThreshold` 仅当 `calibratedAccuracyMedian` 为 null 时回退；当前已填标定值，正常路径不走 fallback。采集口径：`__SNAPSHOT__.calibSummary()`（Σ命中/Σ开枪 池化，n=14）。

- Rationale ✅：S 要求“快+准+稳”三合一，A 只要求准和稳。若 ⚗️ S 达成率 >40%，阈值上调 5-10%。
- 结算屏现状（score/kills/headshots/accuracy/combo）不动，只把评级字母逻辑换掉。

## 7. 存档与解锁（localStorage）

```json
// key: "wk.pve.save.v1"
{
  "schemaVersion": 1,
  "revision": 7,
  "unlocked": 3,
  "weapons": ["ak47", "shotgun"],
  "levels": {
    "1": { "bestGrade": "A", "bestScore": 4200, "clears": 3, "bestCombo": 12 },
    "2": { "bestGrade": "S", "bestScore": 5100, "clears": 2, "bestCombo": 18 }
  }
}
```

| 规则 | 说明 |
|---|---|
| 写入时机 | **仅过关结算时**（unlock 下一关 + bestGrade/bestScore 取优 + clears+1 + 发武器）；阵亡不写盘 |
| 读取失败 | JSON 解析异常 → 原值备份到 `wk.pve.save.v1.backup`，重置新档，HUD 角标提示"存档已重置" |
| 写入失败（隐私模式等） | 降级为内存档，当次会话正常玩，选关界面角标"存档不可用，进度不保留" |
| schemaVersion 不匹配 | 同上备份重置（v1 无迁移逻辑，字段预留） |
| 通关 L7 后 | 全关可重玩刷 S/分数；`unlocked` 封顶 7 |
| 分数/combo 语义 | 每关独立统计，结算后写入 `levels[n].bestScore`/`levels[n].bestCombo`，不跨关累计 |
| 多标签页并发 | read-modify-write + `revision` 乐观锁；监听 `storage` 事件，检测到外部标签页改写时合并 `bestGrade/bestScore` 取优，不整体覆盖 |
| 存档配额 | 7 关 × 单关 <200B，总计 <2KB，远低于所有主流浏览器 5MB 下限；无配额处置需求 |

**选关 UI**：开始屏加「选择关卡」→ 7 张卡片（编号/名称/最佳评级徽章/最佳分数；锁定卡置灰 + 🔒 + "通关上一关解锁"）；结算屏加「下一关」直进按钮（过关且未到 L7）；暂停屏加「放弃本关」回选关。风格沿用现有峡谷 UI，移动端卡片两列。
