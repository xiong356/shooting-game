### 改动文件

- `.workbuddy/memory/MEMORY.md` — 补 8 条约定
- 无 HTML / CSS 改动（血条那样的 3D 化思路：摆动纯在相机上做，不加 DOM）

### 关键设计
1. **`isMoving` 从函数局部提升为模块级 `locomotion` 状态对象** —— 原来相机与音效取不到它，
   且武器 bob 速率与速度硬耦合，三方必须共享同一份数据。
2. **相位只在 `updateLocomotion` 内推进**，而它只被 `updateMovement` 调用（`playing` 块内），
   这条调用链是「暂停时相位不推进」的**结构性保证**，不是靠额外判断。
3. **脚步与视觉同源**：摆动垂直分量 `-amp*cos(2φ)` 在 φ=kπ 取最低点，脚步触发
   `stepsTriggered()` 判的也是跨 π 整数倍 —— 同一个 `Math.PI` 常量定义两者，结构上不可能不同步。
4. **步频由等效步幅导出**而非按档位写死：摇杆推杆深度会缩放速度，写死步频会让半推杆时脚打滑一倍。
5. 速度模型抽成 4 个纯函数（`getTargetMoveSpeed` / `readSprintInput` / `getStepRate` / `stepsTriggered`），
   便于源码抽取做数值验证。

### ⚠️ 抓到的真实缺陷：摇杆双重缩放（探针决定性证据）
旧代码 `if (moveDir.length() > 1) moveDir.normalize()` —— 半推杆时长度 0.5 **不会被归一化**，
幅度同时留在 `moveDir` 里又乘进 `locomotion.speed`，**缩放两次**。

- 现象：`speed` 报 2.1，实测位移速度只有 **1.051**
- 键盘满杆长度恰好 1.0，所以**只在摇杆模拟量下暴露**，读代码看不出来
- 修复：`if (moveDir.length() > 0) moveDir.normalize()`，幅度统一交给 `locomotion.speed`
- **抓到它的手段是「位移法」探针**（用 playerX/playerZ 实际位移除以时间），单看 `speed` 变量是假的

### 顺带修掉的三个既有输入缺陷
都是 `input.shootPressed` 卡死路径，加了开枪减速后会升级成「玩家被永久压在 2.4 m/s」：
1. 移动端**全文件零个 `touchcancel`**（joystick / look / shoot 三处）—— 曾误以为摇杆有，实测没有
2. 桌面 `mouseup` 挂在 canvas 上，指针锁定丢失时收不到 → 改挂 `window`
3. `startGame()` 不复位 `input.shootPressed` → 按住扳机结束对局，新局开局即自动开火
4. 附加：`pauseGame()` 清 `keys`，防 Alt-Tab 卡住 Shift 导致恢复后一直疾跑

## [19:30~20:00] 修复 BUG: 墙和柱子可以穿过

### 现象
玩家可以直接穿过场地里的墙和柱子。

### 排查结论
- **外围边界墙其实是有碰撞的** —— `updateMovement` 末尾的 clamp（x∈[-26,26], z∈[-46,12]）一直在生效。
  之前没意识到这一点，差点重复实现。
- 真正没有碰撞的是 **9 个内部障碍**：2 个射击道隔断 + 7 根掩体柱。

### 方案
1. 新增 `solidObstacles`（XZ 平面 AABB 数组）+ `registerSolid()`。
2. **让几何体自己登记碰撞体** —— `createDivider` / `createPillar` 内部调用 `registerSolid`，
   而不是在 `env.add(...)` 那里另写一份坐标。这样挪柱子时碰撞盒自动跟随，两边不会各改各的。
3. `resolveObstacleCollisions(pos)`：圆 vs AABB 推出。
   **推出方向沿最近点法线 → 天然支持贴墙滑行**（只有法向分量被抵消，切向保留），
   这是相比「逐轴 clamp」的关键优势。
4. 调用顺序：应用移动 → `resolveObstacleCollisions` → 边界 clamp。
   反过来会让贴边柱子把玩家推出去再被 clamp 推回来，产生抖动。

### 数值
- `PLAYER_RADIUS = 0.4`，`COLLISION_ITERATIONS = 2`（处理凹角）
- 隔断 AABB：X∈[-8.15,-7.85] / [7.85,8.15]，Z∈[-11,3]，高 1.8
- 柱子 AABB：1.2×1.2，高 3

### ⚠️ 过程中发现的一个真实约束（不是 bug）
测试构造了「两根柱子间隔 0.1m、玩家塞在缝里」的用例，解算**无解** ——
玩家直径 0.8m 塞不进 0.1m 的缝，两个盒子会互相把玩家推来推去。
这是**关卡摆放约束，解算器修不了**（圆 vs AABB 推出的固有性质）。
处理方式：在 `registerSolid` 里加间距检查，间距 < 玩家直径时 `console.warn`，
把问题暴露在摆放阶段。当前 9 个障碍最近间距约 20m，实际不会触发。
